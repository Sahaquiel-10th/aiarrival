# 投放数据后台说明

## 后台入口

- 正式地址：`https://www.aiarrival.cn/data-center`
- 登录账号和密码只保存在正式服务器，不写入 Git 仓库。
- 登录会话有效期为 12 小时，Cookie 为 HttpOnly、Secure、SameSite=Strict。

## 统计范围

后台默认汇总最近 30 天访问数据，并展示全部客户留资：

- 去重访问人数
- 页面浏览次数
- 平均停留时间
- 按页面拆分的人数、浏览量与停留时间
- UTM 来源与自然来源
- 按钮、链接点击次数
- 创始人版、专家版、官网与知识分身页面
- 快速诊断留资、联系方式与深度诊断完成状态

访客通过匿名随机编号去重，不采集姓名、手机号等身份信息；只有客户主动提交诊断后，联系方式才进入留资记录。

## 正式服务器首次配置

部署代码后，在服务器创建 `/opt/aiarrival-website/shared/admin-auth.json`。文件内容包含管理员账号、PBKDF2 密码摘要、随机盐和会话签名密钥，权限必须为 `600`。

如果使用 `sudo` 创建文件，必须把目录和文件所有权交还给运行网站服务的账号，否则网站进程会把“没有读取权限”误判为“尚未配置”。以当前 `ubuntu` 部署账号为例：

```bash
sudo chown -R "$(id -un):$(id -gn)" /opt/aiarrival-website/shared
sudo chmod 700 /opt/aiarrival-website/shared
sudo chmod 600 /opt/aiarrival-website/shared/admin-auth.json
```

命令正常执行时不会显示成功提示，直接回到命令行属于正常现象，不需要重启网站服务。

配置文件示例：

```json
{
  "username": "admin",
  "passwordSalt": "替换为随机盐",
  "passwordHash": "替换为PBKDF2-SHA256摘要",
  "sessionSecret": "替换为随机会话密钥"
}
```

正式凭据不要复制到项目文件、GitHub Issue 或公开聊天中。更换密码时重新生成盐、摘要和会话密钥，旧登录会话会立即失效。

## 数据位置

- 正式官网访问事件：`/opt/aiarrival-website/shared/analytics.ndjson`
- 正式官网客户留资：`/opt/aiarrival-website/shared/leads.ndjson`
- Sites 备用站：D1 数据库中的 `analytics_events` 与 `lead_requests`

正式服务器文件会在第一次收到事件时自动创建，目录权限为 `700`，文件权限为 `600`。
